Step 8 · Python¶

In this step you read the brews of step 6 from Python, with the same rules as the command line: two scripts, then a few lines typed by hand. A script can also change values, compute and save.

Run every command from this folder, 08-python, with the Python of the .venv/ above the steps, where SampleKit's Python package is installed: ../.venv/bin/python, or python once that environment is active.

Try it¶

$ python scripts/brew_report.py
$ python scripts/yeast_comparison.py

  • brew_report.py prints what is not current, the three best brews, and writes the season to season.csv;

  • yeast_comparison.py compares attenuation and gravity drop by yeast, and draws a figure the project does not declare, yeasts.png.

smoked-porter: abv, attenuation, score

blonde-saison       44.8 ± 0.5   6.1 %
english-pale        44.7 ± 0.9   4.8 %
citra-ipa           42.7 ± 0.9   6.8 %

wrote season.csv

By hand¶

Start python in this folder, and type:

>>> import samplekit as sk
>>> brew = sk.Sample("brews/citra-ipa.md")       # read with its project's model
>>> brew.abv
Property(value=6.825000000000035, uncertainty=0.14510233457805027, unit='%')
>>> brew.abv.value
6.825000000000035
>>> brew["fermentation.gravity[3]"]               # any field the command line reads
1.021
>>> brews = sk.load("brews")                      # a folder: a list of samples
>>> brews.filter("style == ipa").sorted("-abv")   # as -f and -s
>>> print(brews.to_csv(columns=["name", "abv"]))  # as --csv

dir(brew) and help(brew) list what an object offers. A mistake raises a standard exception with the nearest name: brew.abvv is an AttributeError.

Changing, computing, saving¶

>>> brew = sk.Sample("brews/dry-stout.md")
>>> brew.grain_mass.value = 4.5
>>> brew.not_current()
{'efficiency': 'outdated'}
>>> brew.compute()            # what is not current, in your own Python
>>> brew.save()               # writes the file

Reading never computes: a value that is not current is returned as the file holds it, with a warning. save() refuses to overwrite a file that changed since it was read. A script's saves are kept as one snapshot of the project's history, with the script itself:

$ python scripts/yeast_comparison.py
$ samplekit log

The script wrote a figure and saved no brew, and it is still a snapshot, since the figure came from it; samplekit log --script 1 prints the script as it ran.

Why¶

The command line answers the questions you ask often; Python answers the one you have not asked yet. Both read the same files by the same rules, so a script never disagrees with a table.

  • To understand: the history, and what a script leaves in it.

  • To look up: the Python package.

This is the last step. The how-to guides start your own project: moving existing data in, a first model.
