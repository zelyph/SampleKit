Step 1 · First brews¶

In this step you look at three brews, each written by hand in a text file, and read them with your first commands: a list, a table, one brew whole, a filter.

Run every command from this folder, 01-first-brews.

What is here¶

01-first-brews/
  .samplekitrc          marks this folder as a project
  README.md             this page
  brews/
    citra-ipa.md        one brew
    farmhouse-saison.md
    oatmeal-stout.md

.samplekitrc is the project's configuration. For now it says only two things: read the subfolder brews/ too, and skip this README.md, which is not a brew.

schema_version = 1

[collection]
recursive = true
exclude = ["README.md"]

Each brew is one Markdown file. Open brews/citra-ipa.md in any text editor:

---
schema_version: 1
name: citra-ipa
style: ipa
yeast: US-05
brewed: 2026-01-24
properties:
  og: 1.064
  fg: 1.011
  volume: {v: 20.5, unit: L}
---
# Citra IPA

Dry hopped on day 4 with 100 g of Citra.

  • Between the two --- lines is the frontmatter, which SampleKit reads.

  • style, yeast and brewed are attributes: words, dates or numbers that describe the brew.

  • og (the original gravity), fg (the final gravity) and volume are properties: measured quantities. A property is a bare number, like og, or a small mapping that adds a unit, like volume. v is the value.

  • After the second --- is the note. It is yours: SampleKit shows it and never changes it.

Try it¶

$ samplekit brews                       # the brews' files
$ samplekit brews -c style,og,fg        # a table of what they hold
$ samplekit view brews/citra-ipa.md     # one brew, whole
$ samplekit brews -f 'og > 1.055'       # the strong ones
$ samplekit list brews                  # what the project holds

What you see¶

samplekit brews prints the path of each brew, one per line. -c (for columns) turns the list into a table:

style       og      fg
──────────────────────
ipa      1.064   1.011
saison   1.052   1.004
stout    1.058   1.016

In a terminal, each row also starts with the brew's name, in grey. When the output goes to a file or to another program, the name is not added: you get exactly the columns you asked for.

view shows one brew whole:

citra-ipa
  tags     —
  style    ipa
  yeast    US-05
  brewed   2026-01-24
  og       1.064
  fg       1.011
  volume   20.5 L

-f (for filter) keeps the brews that match a condition: here the IPA and the stout, whose original gravity is above 1.055. Quote the whole filter with single quotes, so that the shell leaves it alone. list counts what the project holds, and names the command that lists each kind.

The TUI¶

samplekit alone, in a terminal, opens the TUI: SampleKit in full screen, driven by the keyboard. Its start page offers the project you are in; press Enter to open it.

$ samplekit

Move with the arrow keys, open a brew with Enter, go back with Esc. ? lists the keys of the screen you are on, and q goes back to the page you came from — the start page, or the demo's page of steps — where q goes back again, until it quits. Step 7 tours the TUI.

Help¶

$ samplekit --help            # the commands
$ samplekit view --help       # one command, with examples
$ samplekit view -h           # a shorter summary

Why¶

The files are the only store: no database, nothing hidden. What you measured stays readable in any editor and in git, and SampleKit only reads it — until you ask it to write.

  • To understand: a sample and its file.

  • To look up: the commands, what a sample file can hold.
