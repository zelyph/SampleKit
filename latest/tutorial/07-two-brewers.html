Step 7 · Two brewers¶

In this step Ana and Tom each keep their brews in a project of their own, with one model between them. You read both projects in one command, then do in the TUI, with the keyboard, what the earlier steps did with commands.

What is here¶

07-two-brewers/
  ana/
    .samplekitrc        Ana's project: [model] path = "../shared/brew.py"
    brews/
  tom/
    .samplekitrc        Tom's project, the same model
    brews/
  shared/
    brew.py             the model both use
    hydrometer.py

This folder is no project: it only holds the two. A sample follows the nearest .samplekitrc above it, so each brew keeps its own project's units, digits, queries and profiles.

The states of step 4 are here again, split between the two, and Tom's English pale ale was never computed.

Try it¶

Run these from this folder, 07-two-brewers:

$ samplekit status ana/brews tom/brews          # both, each by its own rules
$ samplekit ana/brews tom/brews --profile alcohol
$ samplekit ana/brews tom/brews -c project,name,abv --csv

In the terminal, a command over two projects prints one table per project, headed by its folder:

ana
Brew               Style      Original gravity    Final gravity   Alcohol [%]   Attenuation [%]
───────────────────────────────────────────────────────────────────────────────────────────────
farmhouse-saison   saison       1.051 ± 0.0003   1.004 ± 0.0003     6.2 ± 0.1                92
…

tom
Brew            Style      Original gravity    Final gravity   Alcohol [%]   Attenuation [%]
────────────────────────────────────────────────────────────────────────────────────────────
double-ipa      ipa          1.078 ± 0.0007   1.014 ± 0.0006     8.5 ± 0.2                82
…

A CSV file is one table: the project column tells the rows apart.

The TUI¶

$ cd ana
$ samplekit                  # the start page: Enter opens Ana's project
$ samplekit tui ../tom       # Tom's project, directly

The TUI opens on the collection, one row per brew. Try, in this order:

Key

What it does

/

type a filter, as after -f; Tab completes, Esc clears it

s

sort by a column; r reverses

c

choose the columns

g

group by a field

f

apply a saved query or profile

Enter

open the brew under the cursor

e

in a brew, change the value under the cursor

N

in a brew, write its note; Esc shows the change

→

in a brew, open the table under the cursor

c

in a brew, compute the value under the cursor

C

compute what is not current

v

the control screen: everything not current or wrong

H

the history, change by change

u

take back the last change

p

a figure or an export

W

save what is shown as a query, a profile or an export

?

every key of the screen you are on

q

back to the start page; q again quits

Whatever you type — a filter, a value, a name, the note — is edited as in a text editor: the mouse or Shift and the arrows select, Ctrl and the arrows move by word, Ctrl+Backspace takes a word back, Ctrl+Z undoes. In the note, Alt+1 to Alt+6 make a heading, Alt+L a link, and * put around a selection makes it emphasis.

Every change is shown before it is written, as the commands' previews are, and y writes it. Marks tell a value's state: ⚠ not current, ✎ written over its formula, ✗ failed, ∅ never computed or waiting.

The TUI remembers, for each folder, the filter, the sort, the grouping and the columns, and opens there next time.

Why¶

A project is a folder with its own configuration and its own model. Keeping people or experiments in separate projects lets each keep its rules, and a command can still read them together without mixing them up.

  • To understand: projects, and a collection over several.

  • To look up: every key of the TUI, which configuration applies.

  • To do: share a project.
