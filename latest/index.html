SampleKit¶

Sample data in plain Markdown: computed, current, tracked.

Every experimental project ends up with the same questions. Which value was computed from which measurement? Was this table made before or after the thickness was measured again? Is the figure in the draft still right? Spreadsheets cannot answer them, and a database keeps your data in a format that only its own software can read.

With SampleKit, each sample is one Markdown file that you can open in any editor, and the answers come with it:

  • computed: the values that derive from your measurements are computed by formulas you write in Python;

  • current: SampleKit knows which results still rest on the measurements they were computed from, and tells you which do not, and why;

  • tracked: every change is kept in the project's history, with the command that made it. The history is a git repository that SampleKit runs itself: you need neither to install git nor to use it.

Install¶

SampleKit is a command line, samplekit, and a Python package of the same name. With Rust installed, cargo builds the command line on any system; then, in a folder of your own, init makes it a project, with its own Python environment holding the package, where your formulas run:

cargo install samplekit --locked --version 1.0.0-rc.2
samplekit init --write

Install SampleKit gives each step, on Linux, macOS and Windows: without Rust, from a release's archive; and the package by pip or uv, into an environment of your own.

What SampleKit guarantees¶

  • Reading computes nothing. Values are computed when you ask, never as a side effect of looking at them.

  • Nothing is written without a preview. Every command that changes a file shows the change first; --write confirms it.

  • Your note is yours. The text below the data is never rewritten, unless you ask: set note=… replaces it.

  • A failure stays visible. A formula that fails is marked as failed, with its error: its old number is never passed off as current, and a file written from it says so, and ends with an error.

  • Plain files, always. No database, no binary format: if SampleKit disappeared tomorrow, your data would still be readable.

Samples and projects¶

The rest of this page builds one example, a step at a time: a few material specimens, tested in tension. SampleKit carries it as a demo in five steps, each a project to try the commands on: samplekit alone opens the start page, where g, then The demo, writes it and opens its first step.

One sample, one file¶

A sample is a Markdown file. At the top, between the --- lines, are its data; below is a free note, which SampleKit keeps as you wrote it (the file's format):

samples/steel-01.md¶
---
schema_version: 1
name: steel-01
material: steel
grade: S355
direction: L
tested: 2026-03-04
properties:
  width: {v: 12.51, unit: mm}
  thickness: {v: 2.0, unit: mm}
---
Tested at 2 mm/min, along the rolling direction.

material, grade, direction and tested are attributes: free facts about the sample. width and thickness are properties: what was measured, with a value v and a unit (samples and their files). A sample may also carry tags, tags: [reference, rerun], words that group samples across their attributes: samplekit tag add writes them, and a filter selects by them. Being plain text, the file opens in any editor, and fits wherever text does: a note-taking app, a synchronised folder, or a git repository if you use one.

A project: a folder of samples¶

A project is a folder holding such files, and a .samplekitrc that marks it as one (projects):

tensile-tests/
├── .samplekitrc          marks the folder as a project
└── samples/
    ├── aluminium-01.md   one file per sample
    ├── copper-01.md
    └── steel-01.md

.samplekitrc is where the project's settings will go. For now it holds one line, the version of SampleKit's format the project is written in:

.samplekitrc¶
schema_version = 1

Reading them: lists, columns, filters¶

That is all SampleKit needs. From the project's folder, samplekit . lists the samples:

~/tensile-tests¶
$ samplekit .
samples/aluminium-01.md
samples/copper-01.md
samples/steel-01.md

A command reads from left to right: samplekit, the program; then what to read. . is the folder you are in, read with every folder below it, samples/ here; a command that names no folder reads the same. A folder or a file named, such as samples/steel-01.md, is read alone (which folders a command reads). Given nothing else, it lists the samples' files, one per line.

samplekit alone, with nothing after it, opens the terminal interface: a full-screen view of the same samples, where what this page does with commands is done with the keyboard. It lists and filters the samples, opens one, changes a value, computes, draws a figure, runs a script and reads the history.

Name columns with -c, by the names the files use, and the list becomes a table:

~/tensile-tests¶
$ samplekit -c material,grade,width,thickness
name           material    grade     width [mm]   thickness [mm]
────────────────────────────────────────────────────────────────
aluminium-01   aluminium   6061-T6        12.50             1.99
copper-01      copper      C11000         12.50             2.00
steel-01       steel       S355           12.51             2.00

name was not asked for: in a terminal, SampleKit adds it first, dimmed, so that each row says which sample it is. In a pipe or a file, a table holds only the columns asked for, and -c name,… asks for it. [render] identify in .samplekitrc adds the file's name instead, or nothing (the setting). The units come from the files.

A filter selects the samples you ask about:

~/tensile-tests¶
$ samplekit -f 'material == aluminium || direction == T' -c material,direction
name           material    direction
────────────────────────────────────
aluminium-01   aluminium   L

-f takes a condition written with the fields' names: ==, !=, <, >, && for and, || for or, ! for not, and words such as has or is missing (filters). Here, the aluminium specimens, and those cut across the rolling direction, T. The quotes keep the shell from reading || itself.

Checking them¶

validate reads every file and says what is wrong in it, before a table or a formula reads it wrong: a file that does not read, a unit that contradicts the others, a value outside the range the project declares. Here, a fourth specimen whose width was typed in centimetres:

~/tensile-tests¶
$ samplekit validate
  copper-02              width: two units — mm on 3, cm on 1

4 samples · 1 defect · 0 notes
error: 1 defect in 1 file

That specimen was a trial, and its file is removed, samplekit samples/copper-02.md remove --write: the rest of this page goes on with the three specimens. It exits with an error while a defect remains, so that a script or a continuous integration job stops there (check a project in continuous integration).

The model: what a sample holds¶

Everything so far works without anything more. But keeping a project by hand is not what SampleKit is for: a spreadsheet does that well enough. SampleKit starts to work for you once it knows what a sample is.

That is the model: a Python class, in a file beside the samples, that declares what a specimen holds and in which units (a model and its formulas):

model/specimen.py¶
import samplekit as sk


class Specimen(sk.Sample):
    """A tensile specimen: what it holds, and in which units."""

    def __init__(self, path=None, name=None):
        super().__init__(path, name=name)

        # Measured with a micrometer.
        self.width = sk.Property(unit="mm")
        self.thickness = sk.Property(unit="mm")

The project's .samplekitrc names it, in a [model] section: the file, the class in it, and the Python environment that runs it (a folder made with python -m venv, holding the samplekit package).

.samplekitrc¶
schema_version = 1

[model]
path = "model/specimen.py"
class = "Specimen"
python = ".venv"

SampleKit can also write the files for you. new creates a sample in the folder you name, with its fields given as field=value, and set changes the fields of an existing one, as in samplekit samples/steel-01.md set thickness=2.01 (new and set in the reference). Now that the model declares the width and the thickness in millimetres, a value given this way is written with its unit, rather than as a bare number:

~/tensile-tests¶
$ samplekit samples new steel-03 material=steel width=12.5 thickness=2.0

Like every command that changes a file, new first shows what it would write and asks before writing. Here the answer was no, so nothing was written. samplekit validate checks every file against the model: a thickness written thin, rather than a number, is a defect. And the model is where the formulas will go, as the next sections show.

Readings and their statistics¶

The width and the thickness are not known exactly: each was measured three times with a micrometer, and the values written so far were means worked out by hand. Write instead what was read, in place of each value, in every sample:

samples/steel-01.md¶
---
# … the attributes, as above …
properties:
  width: {readings: [12.494, 12.528, 12.518], unit: mm}
  thickness: {readings: [1.995, 2.004, 2.008], unit: mm}
---
Tested at 2 mm/min, along the rolling direction.

and say, in the model, how readings give a value (readings and their statistic):

model/specimen.py¶
import samplekit as sk


class Specimen(sk.Sample):
    """A tensile specimen: what it holds, and in which units."""

    def __init__(self, path=None, name=None):
        super().__init__(path, name=name)

        # Measured three times with a micrometer: the value is the mean of the
        # readings, and the uncertainty their standard error.
        self.width = sk.Property(
            unit="mm",
            value=sk.stats.mean,
            uncertainty=sk.stats.standard_error,
        )
        self.thickness = sk.Property(
            unit="mm",
            value=sk.stats.mean,
            uncertainty=sk.stats.standard_error,
        )

Where no precision is declared, an uncertainty is shown to two significant digits, and its value to the same decimal place, as the GUM (the international guide to measurement uncertainty) recommends; declaring one is shown further on (values and their uncertainty). In a column, SampleKit may drop the second digit so that every row has the same decimals: 0.0038 is shown 0.004 beside 0.010. An uncertainty that starts with a 1 always keeps two digits: rounded to one, 0.014 would lose almost a third of itself. Only the display is rounded: the file keeps every digit.

The value v now has an uncertainty u, and both sit beside the readings they come from. An uncertainty known otherwise, such as an instrument's resolution, can also be written by hand: {v: 12.5, u: 0.01, unit: mm}. computed and fingerprint are a short record of those readings: you never write it by hand. It is how SampleKit tells, later, whether the value still holds: if a reading is corrected, it knows (what makes a value current, the fingerprints).

Values computed from others¶

The cross-section \(A\) is the width \(w\) times the thickness \(t\), and its uncertainty \(u_A\) follows from theirs:

\[ A = w\,t \qquad u_A = \sqrt{(t\,u_w)^2 + (w\,u_t)^2} \]

The model holds this formula, and names the values it reads:

model/specimen.py¶
import math
import samplekit as sk


class Specimen(sk.Sample):
    """A tensile specimen: what it holds, and in which units."""

    def __init__(self, path=None, name=None):
        super().__init__(path, name=name)

        # … the width and the thickness, as above …

        # The cross-section, computed from the width and the thickness.
        self.area = sk.Property(
            unit="mm²",
            compute=self._area,
            depends_on=["width", "thickness"],
        )

    def _area(self):
        """The width times the thickness, and its uncertainty from theirs."""
        w = self.width
        t = self.thickness
        value = w.value * t.value
        # A size typed without its readings has no uncertainty: nor has the area.
        if w.uncertainty is None or t.uncertainty is None:
            return value
        uncertainty = math.sqrt(
            (t.value * w.uncertainty) ** 2
            + (w.value * t.uncertainty) ** 2
        )
        return value, uncertainty

area is a property like the width, with two more keywords:

  • compute names the method that gives it. Here _area returns the value and its uncertainty together, as a pair; a method that returns a number alone gives a value without uncertainty. Two other keywords split the work when that is clearer: compute_value for the value alone, beside an uncertainty given another way, and compute_uncertainty for the uncertainty alone, such as an instrument rated at 0.5 % of its reading.

  • depends_on names what the formula reads. SampleKit uses it to compute the width and the thickness before the area, and to know that the area is out of date as soon as one of them changes. It cannot see inside the method: a value read and left out of depends_on would never make the area out of date.

A model and its formulas says more, and the Python reference lists every keyword of sk.Property.

A table inside a sample¶

In the sample's file¶

A tensile test pulls the specimen until it breaks. At each step, it reads the strain, how much longer the specimen has become in %, and the force. These points form a curve, which the file holds as a table, below the properties. The table first names its index, the column whose values identify the rows (here the strain), then lists its columns, then holds one row per point (tables in a file):

A column computed row by row¶

The stress is the force divided by the cross-section, \(\sigma = F / A\). There is one stress per row, not one per sample: it is a column of the table, computed row by row.

The model declares the table with sk.Table: its columns, then its index. Each column is an sk.Property, as in the rest of the model, and takes the same keywords: a unit, and for a computed column compute and depends_on.

model/specimen.py¶
class Specimen(sk.Sample):
    """A tensile specimen: what it holds, and in which units."""

    def __init__(self, path=None, name=None):
        super().__init__(path, name=name)

        # … the width, the thickness and the area, as above …

        # The test: the force read at each strain, and the stress computed
        # in each row from that row's force and the cross-section.
        self.curve = sk.Table(
            {
                "strain": sk.Property(unit="%"),
                "force": sk.Property(unit="kN"),
                "stress": sk.Property(
                    unit="MPa",
                    compute=self._stress,
                    depends_on=["row.force", "area"],
                ),
            },
            index="strain",
        )

    # … _area, as above …

    def _stress(self, row):
        """The force over the cross-section: kN over mm², times 1000, is MPa."""
        return 1000 * row.force.value / self.area.value

The only difference with a property is what the method is given. The area's method, _area, takes nothing but self, the sample. The stress's method, _stress, also takes row, and runs once for each row: row.force is the force of that row, and self.area the area of the sample, the same in every row. depends_on names them the same way: row.force for the force of the same row, area for the sample's property (formulas over a table).

The stress has no uncertainty here, so nothing says how many digits it deserves. The project says it in .samplekitrc, as a precision, written as in Python's format strings: .1f writes one decimal, .2e two in scientific notation (how many digits).

.samplekitrc¶
# … schema_version and [model], as above …

[property."curve.stress"]
precision = ".1f"

Results computed from a table¶

Four results from the curve¶

Four results are read on the curve:

  • the Young's modulus E, the slope of the curve's straight first part. A line is fitted to the rows up to 0.05 % of strain, and the uncertainty of E is that of its slope;

  • the yield strength Rp0.2, where the metal starts to stretch for good. It is the stress where the curve crosses that same line, moved 0.2 % to the right;

  • the tensile strength Rm, the highest stress;

  • the elongation A, the strain at the break.

Each is a property of the sample, computed from whole columns of the table. In depends_on, curve.strain and curve.stress name these columns, where row.force named a single cell of a row. The methods read them with self.curve.values(...):

model/specimen.py¶
class Specimen(sk.Sample):
    """A tensile specimen: what it holds, and in which units."""

    def __init__(self, path=None, name=None):
        super().__init__(path, name=name)

        # … the width, the thickness, the area and the curve, as above …

        # What the curve gives.
        self.young_modulus = sk.Property(
            unit="GPa",
            compute=self._young_modulus,
            depends_on=["curve.strain", "curve.stress"],
        )
        self.yield_strength = sk.Property(
            unit="MPa",
            compute=self._yield_strength,
            depends_on=["curve.strain", "curve.stress", "young_modulus"],
        )
        self.tensile_strength = sk.Property(
            unit="MPa",
            compute=self._tensile_strength,
            depends_on=["curve.stress"],
        )
        self.elongation = sk.Property(
            unit="%",
            compute=self._elongation,
            depends_on=["curve.strain"],
        )

    # … _area and _stress, as above …

    def _young_modulus(self):
        """The slope of a straight line fitted to the rows up to 0.05 %, and
        the uncertainty of that slope."""
        points = [
            (strain, stress)
            for strain, stress in zip(self.curve.values("strain"), self.curve.values("stress"))
            if strain <= 0.05
        ]
        n = len(points)
        mean_strain = sum(strain for strain, _ in points) / n
        mean_stress = sum(stress for _, stress in points) / n
        spread = sum((strain - mean_strain) ** 2 for strain, _ in points)
        slope = sum(
            (strain - mean_strain) * (stress - mean_stress) for strain, stress in points
        ) / spread
        residuals = [
            stress - mean_stress - slope * (strain - mean_strain) for strain, stress in points
        ]
        uncertainty = math.sqrt(sum(r * r for r in residuals) / (n - 2) / spread)
        # MPa per % of strain, to GPa: times 100, then divided by 1000.
        return slope / 10, uncertainty / 10

    def _yield_strength(self):
        """Where the curve crosses the straight line of slope E, moved 0.2 %
        to the right: interpolated between the two rows on either side."""
        slope = self.young_modulus.value * 10  # GPa to MPa per %
        rows = list(zip(self.curve.values("strain"), self.curve.values("stress")))
        for (e0, s0), (e1, s1) in zip(rows, rows[1:]):
            above0 = s0 - slope * (e0 - 0.2)
            above1 = s1 - slope * (e1 - 0.2)
            if above0 > 0 >= above1:
                return s0 + above0 / (above0 - above1) * (s1 - s0)
        return None

    def _tensile_strength(self):
        """The highest stress."""
        return max(self.curve.values("stress"))

    def _elongation(self):
        """The strain at the break: the last row."""
        return self.curve.values("strain")[-1]

Tables written to files¶

Every table shown so far can also go to a file. -o names the file, and its extension says what to write in it: a data file for another program, or a table to paste into a document.

A file writes each number as the table shows it, at the precision declared for its property or its column. A precision is kept as you give it, for the uncertainty too, which is rounded up, never understated: .1f writes an uncertainty of 0.012 as 0.1, eight times its size. A pair gives each its own, precision = [".1f", ".2g"]: one decimal for the value, two significant digits for its uncertainty. The profile overview gives E a precision of its own, .1f: its uncertainty, about 1 GPa, is written 1.1.

Figures¶

SampleKit draws figures with matplotlib, from the samples and by a command: like a table, a figure is made again whenever the data changes.

From the command line¶

Without -o, the figure opens in a window; with -o, it is written to a file:

~/tensile-tests¶

Each axis is labelled with its field and unit, and the figure has matplotlib's look.

Drawn by the model¶

A declared figure plots one field against another. For anything more, such as a reference line, a fit or several panels, the model draws the figure itself. A method marked @sk.figure is given matplotlib's axes, ax, and draws on them (sk.figure); its docstring says what it shows, and it writes its labels itself. It draws one sample, or the selection:

  • A method draws one sample. samplekit samples/steel-01.md plot yield_point draws steel-01; over several samples, -o 'figures/{name}.png' writes a file for each.

  • Placed above @classmethod, it draws the selection: it is given the samples selected, a list, and draws them together.

Here, one of each: the start of a curve, the line of slope E moved 0.2 % to the right and the yield strength where they cross; then the two strengths of every specimen, side by side:

model/specimen.py¶
class Specimen(sk.Sample):
    # … as above …

    @sk.figure
    def yield_point(self, ax):
        """The start of the curve, the line of slope E moved 0.2 % to the
        right, and the yield strength where they cross."""
        strain = self.curve.values("strain")
        stress = self.curve.values("stress")
        ax.plot(strain, stress, "o-", label="curve")
        slope = self.young_modulus.value * 10  # GPa to MPa per %
        offset = [0.2, 0.2 + self.yield_strength.value / slope]
        ax.plot(offset, [0, self.yield_strength.value], "--", label="offset 0.2 %")
        ax.axhline(self.yield_strength.value, color="0.5", linewidth=0.8)
        ax.set_xlim(0, 1)
        ax.set_xlabel(r"$\varepsilon$ [%]")
        ax.set_ylabel(r"$\sigma$ [MPa]")
        ax.legend()

    @sk.figure
    @classmethod
    def strengths(cls, samples, ax):
        """The yield and the tensile strength of each specimen, side by side."""
        names = [specimen.name for specimen in samples]
        at = range(len(names))
        ax.bar([x - 0.2 for x in at], [s.yield_strength.value for s in samples], 0.4,
               label="Rp0.2")
        ax.bar([x + 0.2 for x in at], [s.tensile_strength.value for s in samples], 0.4,
               label="Rm")
        ax.set_axisbelow(True)
        ax.set_xticks(list(at), names)
        ax.set_ylabel(r"$\sigma$ [MPa]")
        ax.legend()

Scripts¶

A script is a method of the model that does something to samples when you ask it to: an attribute filled from a value, a reading corrected, a report printed, a sample made from others (run a script of the model). @sk.script marks it, and as for a figure:

  • A method runs on each sample selected, in turn.

  • Placed above @classmethod, it runs once on the selection, a list of samples.

  • Its keyword parameters are the command's options, set with --set, typed by their annotation or their default; its docstring says what it does.

Here, one of each: a script that classes each specimen's ductility by its elongation, and one that ranks the specimens by any field:

model/specimen.py¶
class Specimen(sk.Sample):
    # … as above …

    @sk.script
    def classify(self, limit: float = 20.0):
        """Class the specimen's ductility by its elongation at break."""
        self.ductility = "high" if self.elongation.value >= limit else "low"

    @sk.script
    @classmethod
    def ranking(cls, samples, by: str = "tensile_strength"):
        """Print the specimens from the highest value of a field to the lowest."""
        for rank, specimen in enumerate(samples.sorted(f"-{by}"), start=1):
            print(rank, specimen.name, specimen[by])

Files¶

Photos, what the testing machine exported, a report: files that belong to a sample, but are not samples. SampleKit neither stores them nor reads them. It finds them, so that a command, a script or the terminal interface opens them (a sample's own files). .samplekitrc says where they are, in one of two ways:

  • A folder alone, photos: a file in it belongs to a sample when its name starts with the sample's, steel-01-fracture.jpg to steel-01, and so does every file in a folder named after the sample, photos/steel-01/.

  • A pattern holding {name}, the sample's name: machine/{name}/* is every file in the folder the machine wrote for that specimen. * matches within one folder, ** across folders, and {csv,txt} either of the two.

Where two names start alike, the longest wins: s-10.png belongs to s-10, not to s-1. Declared at a root that several projects import, {project} stands for each project's folder, so that "{project}/photos" finds each one's own (organise a project's settings). Here, the photographs in one folder, and the machine's files in a folder per specimen:

.samplekitrc¶
[collection]
files = ["photos", "machine/{name}/*"]

tensile-tests/
├── .samplekitrc
├── machine/
│   ├── aluminium-01/
│   │   ├── curve.csv
│   │   └── settings.txt
│   ├── copper-01/
│   │   └── …
│   └── steel-01/
│       └── …
├── photos/
│   └── steel-01-fracture.jpg
└── samples/
    ├── aluminium-01.md
    └── …

A pattern opens some of them, open '*.jpg' the photograph alone, and --navigate opens the folder holding them instead. samplekit validate says where a pattern of .samplekitrc cannot work, a misspelt {nmae} for one.

A file no name finds, or another sample, is named by a link, an attribute written as Obsidian or Markdown writes one: here the aluminium and copper specimens hold compared_with: "[[steel-01]]", which the terminal interface follows and rename keeps (link samples).

Python¶

The samplekit package reads the same files, with the same names and the same model: it is the one the model already uses, installed in the project's Python environment. A script of your own, outside the model, or a notebook, does with it what the commands do (the Python reference).

Reading¶

load reads a folder as the command line does, its model applied, and gives a list of samples. sorted and filter take what -s and -f take. A property is a value, an uncertainty and a unit, and .value is a number to compute with; to_csv and to_dict give the columns as --csv does (the table printed as CSV rather than drawn), which pandas reads as they are:

report.py¶
import samplekit as sk

specimens = sk.load("samples").sorted("-tensile_strength")
for specimen in specimens:
    ratio = specimen.yield_strength.value / specimen.tensile_strength.value
    print(f"{specimen.name:13} {specimen.tensile_strength}   Rp0.2/Rm = {ratio:.2f}")

print(specimens.filter("elongation > 20").to_csv(columns=["name", "young_modulus"]))

Changing and computing¶

A sample changes as an object does. not_current says what the change made out of date, compute runs the model's formulas, and nothing is written until save:

remeasure.py¶
import samplekit as sk

steel = sk.Sample("samples/steel-01.md")
steel.width.readings = [12.49, 12.53, 12.52]
print(steel.not_current())
steel.compute()
print(steel.area, steel.tensile_strength)
steel.save()
output¶
{'width': 'outdated', 'area': 'outdated', 'young_modulus': 'outdated', 'yield_strength': 'outdated', 'tensile_strength': 'outdated', 'curve.stress': 'outdated'}
24.918 ± 0.031 mm² 521 MPa

sk.plot draws a figure, declared or the model's, and a list's export, specimens.export("paper"), writes an export, as plot and export do; sk.keep records what a script saved as one change of the project's history.
